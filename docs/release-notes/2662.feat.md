Any string can now be used as a mapping key (e.g. in `uns`) or `obs`/`var` column name, e.g. `a/b` ({issue}`2039`) or `a:b`.
This needs new versions of the {ref}`dataframe <dataframe-indexed>` (v0.3.0) and {ref}`mapping <mapping-indexed>` (v0.2.0) specifications, which safely store the {ref}`keys as a list <indexed-keys>`.
Older versions of anndata can’t read these, so they are only written with the `compat="0.14"` {doc}`write compatibility profile </write-compat>` (or `compat=WriteFeatures.INDEXED_KEYS`).

```{note}
This means children of such groups are no longer stored under their key: path access like `f["obsm/X_pca"]` or `sparse_dataset(f["layers/counts"])` raises a {exc}`KeyError`, and {func}`~anndata.experimental.read_dispatched` callbacks see e.g. `/obsm/item_0` instead of `/obsm/X_pca`. Code that accesses files directly needs to check the parent group’s `encoding-version` first.
```
